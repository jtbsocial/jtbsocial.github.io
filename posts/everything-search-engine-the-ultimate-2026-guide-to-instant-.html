What is Everything by voidtools?

Developed by David Carpenter under the banner of voidtools, Everything is an administrative desktop search engine for Windows that locates files and folders by name instantly. Unlike conventional search engines that crawl and index every word within every document line by line, Everything focuses initially on file and directory metadata, making its index extraordinarily fast and lightweight.

Key Highlights:

  • Instant Results: As quickly as you type each letter, file lists filter in real-time.
  • Tiny Index Size: An index containing 1 million file paths consumes roughly 75 MB of disk space and minimal memory.
  • Real-Time Monitoring: Automatically updates its database instantly whenever files are created, renamed, modified, or deleted.
  • Zero Telemetry: Free from tracking, ads, and background telemetry.

Under the Hood: How Everything Achieves Blazing Speeds

To understand why Everything outperforms native OS indexing tools by orders of magnitude, we must examine how it interacts with the Windows File System.

1. Direct NTFS MFT Parsing

Standard OS search utilities rely on high-level file system APIs, requesting directory trees one folder at a time. Everything bypasses this abstraction layer by reading the Master File Table (MFT) directly on NTFS volumes. The MFT is a structural database maintained by NTFS that records attributes for every file and folder on the volume. By opening a raw handle to the MFT, Everything reads the entire directory structure of a multi-terabyte volume in milliseconds.

2. USN Change Journal Integration

To stay updated without continuous disk scanning, Everything monitors the Update Sequence Number (USN) Change Journal. When a file is modified, created, or removed, the NTFS driver writes a log entry to the USN Journal. Everything listens to this event stream in real time, updating its internal RAM index instantly with microsecond latency.

3. ReFS and FAT/exFAT Support

While native real-time indexing is optimized for NTFS, modern releases of Everything seamlessly handle non-NTFS drives—including FAT32, exFAT, ReFS, and networked SMB/NAS shares—by utilizing background index scheduling and folder monitoring hooks.

Mastering Everything Search Syntax & Regex

The true power of Everything unfolds when you leverage its rich search operators and functions. Below is a practical guide to unlocking its query syntax.

Basic Search Operators

Operator / Syntax Description Example Query
space AND operator (matches both terms) report 2026
| OR operator (matches either term) png \| jpg
! NOT operator (excludes term) project !backup
" " Exact phrase match "Quarterly Financial Report"
* Wildcard for multiple characters log_*.txt
? Wildcard for a single character file_??.doc

Specialized Search Functions

  • Filter by Extension: ext:mp4;mkv;avi
  • Filter by Path: path:"C:\Projects\2026"
  • Filter by File Size: size:>1GB or size:10MB..500MB
  • Filter by Date Modified: dm:today, dm:yesterday, or dm:2026-01-01..2026-03-31
  • Find Duplicate Files: dupe: or dupe:name
  • Search File Contents: content:"API_SECRET_KEY" (Note: Content search scans disk files directly and operates slower than name searching).

Regular Expression (Regex) Examples

By toggling Search -> Enable Regex (or pressing Ctrl + R), you can use full Perl-compatible regular expressions:

  • Find files starting with three digits: regex:^\d{3}_
  • Locate log files with specific version strings: regex:app-v[1-9]\.\d+\.log

Step-by-Step Installation and Optimization Guide

Getting started with Everything takes less than two minutes. Follow this optimization setup for ideal performance in 2026.

Step 1: Download the Official Installer

Visit the official voidtools website (voidtools.com) and download the latest stable release (e.g., v1.4.1.x or v1.5 Alpha/Beta branch). Choose between the x64 Installer, Portable Zip version, or lightweight ARM64 binary depending on your system architecture.

Step 2: Configure Service vs. Administrative Privileges

During installation, you will be prompted to choose how Everything accesses system drives:
* Recommended: Install the Everything Service. This runs a lightweight system service in the background, allowing standard non-admin user accounts to access instant NTFS indexing without triggering Windows User Account Control (UAC) prompts on startup.
* Alternative: Run as Administrator directly (only recommended for portable USB setups).

Step 3: Optimize Indexing Settings

  1. Open Everything and navigate to Tools -> Options.
  2. Select Indexes -> NTFS.
  3. Ensure Include in Everything index and Enable USN Journal logging are checked for all local drives.
  4. Under Indexes -> Exclude, add systemic folders you wish to ignore (such as C:\Windows\Installer or $Recycle.Bin) to clean up search noise.

Advanced Use Cases: Remote Servers, CLI, & SDK

Beyond personal file management, Everything serves as a critical asset in enterprise and developer toolchains.

1. HTTP Server for Local Network Indexing

System administrators can turn on the embedded HTTP Server (Tools -> Options -> HTTP Server). This launches a local web interface, allowing team members across a local network to query file paths on a central server via any standard browser without needing SMB network share indexing.

2. Everything Command-Line Interface (ES.exe)

voidtools provides a dedicated standalone tool called ES (Everything Command-line Interface). With es.exe, developers can script file queries directly inside PowerShell, Command Prompt, or automated batch files:

# Example ES Command Line Queries
es.exe -ext pdf "invoice 2026"
es.exe -size +500MB -sort size-desc -export-csv heavy_files.csv

3. Software Development Kit (SDK)

The Everything SDK provides C/C++, C#, and Python bindings. Software developers can query the local Everything IPC database to build ultra-fast file discovery features directly into custom enterprise software applications.

Pros and Cons Breakdown

Pros

  • Unrivaled Performance: Sub-second indexing and zero input lag while typing queries.
  • Minimal Resource Footprint: Runs comfortably even on legacy hardware or low-power mini PCs.
  • No Background Bloat: Zero telemetry, advertising, forced background updates, or web search integration.
  • Powerful Search Logic: Full support for regex, file size filters, date windows, and duplicate file detection.
  • Flexible Automation: CLI integration and SDK access for developers and IT managers.

Cons

  • Windows Only: Native support is restricted to Microsoft Windows environments (Linux/Mac require Wine or alternatives like FSearch/Locate).
  • Content Indexing Overhead: While file name indexing is instant, deep text searching inside document contents requires manual disk reading and takes longer.
  • Requires Administrative Rights for Setup: Installing the background service or reading MFT tables requires initial admin privileges.

Who Should Use Everything?

  • Power Users & IT Professionals: Quickly audit storage space, track down log files, locate duplicate assets, and script system cleanup tasks.
  • Software Developers: Find source code files, build artifacts, configuration files, and dependencies instantly across massive monorepos.
  • Digital Content Creators: Filter through terabytes of raw video footage, graphic assets, audio stems, and project files without breaking creative flow.
  • Everyday Windows Users: Frustrated by slow, unreliable native OS start-menu and File Explorer searches.
